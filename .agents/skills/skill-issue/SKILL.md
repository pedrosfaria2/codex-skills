# Adapt an unsuitable skill

A skill conflict is evidence to investigate, not permission to ignore an
inconvenient rule or create a workaround.

The discovering agent reports the task ID, exact file and rule, observed project
constraint, reproduction or example, affected work, and independent work that
can continue. Workers never edit skills, references, scripts, metadata, or routing.

The primary:

1. Reads the rule, linked material, original convention when available, and actual
   project behavior. Establishes the rule's purpose and whether it applies.
2. Researches relevant official documentation. Separates a technical adaptation
   from a missing user requirement. Preserves explicit user instructions.
3. Explains a correct rule or repairs an unsuitable one at its source. Uses
   existing tools and conventions; avoids parallel rulebooks and compatibility
   scaffolding. Applies [decision-matrix](../decision-matrix/SKILL.md) to choices.
4. Makes the smallest coherent correction and checks all linked instructions
   for contradiction. Validates schema, metadata, links, and the triggering
   scenario; runs behavioral checks and measurements if executable helpers change.
5. Records the cause, correction, checks, and affected task in the plan and
   continuity. Accepts and commits under
   [orchestration](../project-workflow/references/orchestration.md), then informs
   affected workers and resumes dependent work.

Pause only dependent work. Do not weaken an acceptance gate or ask the user to
perform a routine technical adaptation already authorized. Escalate genuinely
missing authorization or requirements precisely.
